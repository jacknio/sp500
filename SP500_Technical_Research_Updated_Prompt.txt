   For EACH indicator, count/aggregate technical states across the selected

   separate from A and B.

 - Each path can be run independently: --run breadth | composite | ml | all.

4A. TECHNICAL BREADTH — MUST WORK WITHOUT MACHINE LEARNING
====================================================================
This is a FIRST-CLASS, INDEPENDENT DELIVERABLE. Build a GENERIC, EXTENSIBLE
aggregation engine, not separate hard-coded RSI plotting logic.

For any configured indicator/state/score, generate daily metrics such as:
 - n_eligible, n_valid, coverage_pct
 - count_true, pct_true = 100 * count_true / n_valid
 - counts/percentages by mutually exclusive states (where applicable)
 - bullish_pct, bearish_pct, neutral_pct, net_breadth = bullish - bearish
 - mean, median, dispersion/std, user-configured share above/below thresholds
 - optional cap-weighted rates with properly aligned weights

SPECIFIC RSI EXAMPLE (REQUIRED):
 pct_oversold_t = 100 * count(RSI_i,t < 30) / valid_RSI_names_t
 pct_overbought_t = 100 * count(RSI_i,t > 70) / valid_RSI_names_t
 pct_neutral_t = 100 - pct_oversold_t - pct_overbought_t
 net_RSI_breadth_t = pct_overbought_t - pct_oversold_t   [percentage points]

Illustrative (NOT real data): if 30% are oversold and 10% are overbought,
net RSI breadth = -20 percentage points; 60% are neutral. Keep all three.
This describes crowding/condition, not an automatically profitable signal.

OTHER EXAMPLE INDICATORS (REQUIRED, USING SAME ENGINE):
 - MACD: % bullish by MACD line above signal; % bearish; net spread;
   % new bullish/bearish crossover events as distinct event breadth.
 - TD: % new Buy Setup 9 completions, % new Sell Setup 9 completions;
   optionally % in late setup (e.g. counts 7–9), always distinguish EVENT
   flags from persistent conditions.
 - Moving average: % price above SMA50, % above SMA200, and their complements.
 - Composite score: % positive, % negative, average/median score, % above
   +threshold, % below -threshold, and net positive-minus-negative spread.

GENERALIZABILITY (VERY IMPORTANT):

4C. OPTIONAL ML STOCK RANKING & LONG/SHORT BACKTEST
====================================================================
"Machine Learning" here means SUPERVISED LEARNING using historically known
technical features to predict realized FUTURE outcomes. It is NOT equivalent
to calculating indicators or counting oversold stocks.

 - Create features as of close(t): RSI, MACD, TD, MA, returns, vol, volume,
   optional composite; every feature must be available by t. Do not use
   future cross-sectional memberships, standardized values, or labels.
 - Define and document ONE primary target and execution convention. Suggested:
   forward 5-trading-day stock return minus forward 5-day SPY return, measured
   over an explicitly tradable holding interval after the signal. Example:
   signal after close(t), first trade at next day's close(t+1), exit close(t+6).
   Do not use close(t) as executable if the signal needs close(t) information.
   Historical targets near the sample end are missing until fully observed.
 - Begin with transparent regularized Logistic or Ridge model. Optional
   secondary gradient boosting ONLY after baseline is working.
 - Train pooled cross-sectionally as justified; document label frequency and
   dependence across tickers. Fit scalers/encoders on TRAINING samples only.
 - Time-ordered EXPANDING/WALK-FORWARD split, never random train/test.
   Purge overlapping forward-label windows: use a training observation ONLY
   if its ENTIRE outcome/exit window is known strictly before prediction time.
   Avoid survivorship, lookahead, calendar alignment, and overlap leakage.
 - Keep training history (ideally 3–5 years) independently configurable from
   plotted 1-year breadth history. Do not claim 10 stocks and 1 year prove alpha.
 - Every eligible date/ticker: predicted excess return or probability (clearly
   named), raw ML prediction, daily cross-sectional percentile ML score 0..100,
   rank, long/neutral/short label (top 20%, middle 60%, bottom 20%).
 - Use a deterministic tie rule and explicitly handle small universe sizes,
   low valid coverage, and days with NO TRAINED MODEL. Do not invent scores.
 - Save out-of-sample predictions ONLY for validation/performance reporting.
 - Evaluate daily Spearman rank IC against realized forward excess returns,
   AUC if valid, hit rate, coverage, turnover, and correct basic diagnostics;
   output NaN and explanation where metrics cannot be computed.
 - Optional correct backtest: rank-based long/short with clearly defined
   rebalance interval, position/weight constraints, execution timing,
   overlapping 5-day holding cohorts if supported, trading costs and turnover.
   If using simpler daily one-day-holding strategy, explicitly label the
   horizon mismatch and avoid crediting returns before entry.
 - CRUCIAL: Top/Bottom 20% shares and average DAILY percentile rank are nearly
   fixed by construction; these must NOT be marketed as informative index
   sentiment/breadth series. If aggregating ML at index level, use raw
   probabilities/expected returns and coverage, explicitly labelled "ML".
 - If too little history for a credible ML walk-forward run, report this and
   SKIP ML performance while successfully completing A) and B).
